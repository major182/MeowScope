**何を、どの種類のテストで、どんな考え方で確かめるか**を決める文書。
一つひとつの入力値と期待する結果は、テストのコードに書く（コードが正）。

---

## 1. テストの区分

| 区分 | 何を確かめるか | 差し替えるもの | 使う道具 |
|---|---|---|---|
| 単体テスト（UT） | 関数・クラス・コンポーネントを単独で | DB・外部 API・他の層 | flutter_test、JUnit |
| 結合テスト（IT） | API・画面の単位で、層をつないで | 差し替えない（実際の DB を使う） | Spring Boot Test、Testcontainers（PostgreSQL 18.6 をコンテナで動かす。Docker が必要） |
| E2E テスト（E2E） | 主要な操作を、画面から一連の流れで | 端末の DB とトークンの置き場だけをメモリーに（サーバーと通信は本物） | integration_test（Windows と Android で同じテスト。手元の Docker のサーバーが必要） |

## 2. 観点の出し方

- 単体：分岐網羅（C1）を目標にする。同値分割・境界値
- 結合：設計書のステータス・エラー・権限（デシジョンテーブル）・状態遷移

## 3. テストの名前の付け方

テストの名前は「テスト ID ＋ 確かめる内容」とし、ID は `区分-機能-連番` とする（例：`UT-RC-05 標準の8項目を並び順どおりに登録する`）。機能の略号は次のとおり。

| 略号 | 機能 |
|---|---|
| RC | 記録（項目・記録の保存と取得） |
| HM | ホームの画面 |
| HH | おうち（作成とセッション） |
| CT | 猫（登録） |
| ST | 起動から記録までの流れ |
| SH | メニュー（画面の切り替え） |
| RD | 記録の詳細（入力の決まり・更新・削除） |
| RS | 記録の詳細入力と詳細の画面 |
| CL | カレンダー（日付の計算・印・期間の取得・週の始まり） |
| CS | カレンダーと日別一覧の画面 |
| SS | 統計（集計と画面） |
| CP | 猫の一覧とプロフィール（編集・お別れ・削除） |
| TY | 記録項目の設定と独自の項目 |
| SE | 設定の画面 |
| HD | 独自の項目の非表示と、端末の DB の版の更新 |
| AU | 認証（アプリ：入力の決まり・通信の部品・ログインとログアウト・画面。サーバー：結合テスト） |
| SY | 同期（アプリ：送受信・反映・自動の同期・S-46。サーバー：結合テスト） |
| PH | 写真（縮小・保存・30日・同期・表示。サーバー：送信と取得） |
| MG | おうちの管理とアカウント（S-42、S-45、抜ける、退会） |
| LO | 端末のログと問い合わせ（記録・送信・書き出し・S-06。サーバー：IT-CL） |
| IC | ユーザーと猫のアイコン |
| IV | 招待（リンクの作成・受諾・参加の画面） |
| AS | 認証（サーバーの単体：回数制限・署名鍵・トークンのハッシュ） |
| LG | サーバーのログ（JSON の形・重大度・リクエストの ID・アクセスログ） |
| ER | サーバーのエラーの形式（RFC 9457） |
| DB | サーバーの DB の変更管理（Flyway） |
| WB | ウィジェットのボタン（保存・同期・S-44） |
| WG | Android のウィジェット（Dart：渡す内容・裏側の記録。Kotlin：表示と動き。JUnit） |
| RJ | 送れなかった変更（理由の保存・原因と対応の案内・S-48） |
| PR | パスワードの再設定（確認コード・メール送信・S-03。サーバー：IT-PR） |
| JA | 日本語の表示（ロケール） |
| PG | 削除から90日を過ぎたデータの片付け（サーバー：IT-PG） |
| E2E | 主要な操作の一連の流れ（NF-MT-02） |

端末内 DB を使う単体テストは、メモリー上の SQLite（`test/helpers/test_db.dart`）を使い、テストごとに空の状態から始める。

## 5. カバレッジ

CI で計測し、しきい値を下回ったら失敗させる。

| 対象 | しきい値 |
|---|---|
| アプリ（Flutter） | 行 80%（`app/tool/check.dart`）。自動生成のコード（`*.g.dart`）と drift の表の定義（`tables.dart`）は、実行されないので除く |
| サーバー（Spring Boot） | 命令 80%（JaCoCo） |

## 6. 実行の方法

```powershell
cd app; dart run tool/check.dart --all
```

CI も同じ内容を実行する。
Android のウィジェットの Kotlin の単体テスト（UT-WG-01〜10）は、同じコマンドの中で `app/android` の `./gradlew :app:testDebugUnitTest` として動く。カバレッジの計測は Dart だけを対象にする。

### E2E テスト

端末とサーバーが要るので、CI では動かさず、手元で動かす。サーバーを `docker compose up -d` で起動し、Android はエミュレーターを起動しておく。

```powershell
cd app; dart run tool/e2e.dart windows   # Windows（開発者モードが必要）
cd app; dart run tool/e2e.dart android   # Android のエミュレーター（サーバーには 10.0.2.2 でつなぐ）
```

スクリプトは、サーバーが動いているかを確かめてから、端末に合わせた接続先（`API_BASE_URL`）を渡して動かす。端末の DB とトークンの置き場はテストの側でメモリーに差し替えるので、端末のデータは使わない。アカウントは毎回新しく作る（`e2e-*@example.com`）。

Android で動かすと、端末のアプリはテスト用のものに入れ替わり、ホーム画面に置いたウィジェットも外れる。終わったら普通のアプリを入れ直す。
