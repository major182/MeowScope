## 1. この文書の目的

MeowScope で採用する技術、バージョン、選定の理由を記録する。

## 2. 選定の条件

- Windows desktop と Android を対象とし、Android のウィジェットとバックグラウンド処理を作れる
- オフラインで記録でき、サーバーが停止していても動く
- ランニングコストを可能な限り発生させない
- AWS から開発者の PC の Docker へ移しやすい
- LTS がある技術は最新の LTS、ない技術は最新の安定版を使う
- 将来の iOS 対応を妨げない

## 4. 主な設計判断

- **同期は自作する。** 差分同期、削除の同期、競合の解決（BR-10、BR-11）をサーバーとアプリの両方に実装する
- **守りはサーバーに置く。** アプリは解析される前提で、認証と認可をすべてサーバーで行う（NF-SC-04）
- **OS に依存する部分を分離する。** 検知の判定は Dart の独立した部分に置き、ウィジェットとバックグラウンド処理はアプリ本体から分ける。将来の iOS では、ウィジェットを Swift で作り直し、判定を伴う通知はサーバーからのプッシュ通知を検討する
- **更新トークンは DB で管理する。** ランダムな値のハッシュだけを保存し、更新のたびに交換して、使い回しを検知したら全トークンを無効にする（06 API 設計書 2章）。JWT の署名鍵は秘密の置き場に置く
- **AWS 固有の機能に依存しない。** 移行は Compose の定義、DB のダンプ、写真のボリュームを移すことで行う
- **メール送信はインターフェースで分ける。** 将来の公開時に送信サービスへ差し替えられるようにする。アプリパスワードは秘密の置き場に置く

## 5. 配布物への署名（検討中：Q-27）

Android 版は、自分で作る鍵で無料で署名する。鍵は秘密の置き場に置き、リポジトリに入れない。

Windows 版は、費用がかかるため保留する。署名しない場合、初回の起動で SmartScreen の警告が出る（「詳細情報」→「実行」で起動できる）。2026-11-03 に調べた選択肢は次のとおり。

| 方法 | 費用（目安） | 条件と注意 |
|---|---|---|
| 署名しない | 無料 | 警告が出る。2人の利用なら運用で回避できる |
| 自分で作る証明書 | 無料 | 利用する PC に証明書を入れれば警告は消えるが、他の PC では効果がない |
| SignPath Foundation | 無料 | オープンソース向け。OSI が認めるライセンスが必要で、今のリポジトリにはライセンスがない。審査がある |
| Azure Artifact Signing | 月額の料金（料金表で確認） | 個人での登録は米国・カナダに限られ、日本からは利用できない |
| OV のコード署名証明書 | 年 3〜6 万円程度（約 220〜440 USD） | 個人でも取得できる。鍵は専用の機器かクラウドの HSM に置く必要がある。有効期間は最長 460 日で、毎年の更新が必要 |

価格は販売店の表示で、時期により変わる。決めるときに改めて確認する。
