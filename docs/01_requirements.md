## 1. はじめに

- 目的：猫の日々の体調を記録し、いざという時に、いつもと何が違うかを利用者が判断できるようにする
- 対象とする利用者：開発者を含む限られた利用者（2人を想定）。一般公開はしない

## 2. システム化の概要

- 対象プラットフォーム：Windows desktop、Android スマートフォン
- Android 版はウィジェットを備え、利用者が登録したボタンで「ご飯食べた」などをワンボタンで記録できる
- 端末の役割を分ける。ふだんの記録は Android で行い、Windows は統計をより細かく見る道具と CSV の出力を中心にする（Windows でも記録はできる）
- 記録はサーバーに保存して端末間と利用者間で共有する。通信できないときやサーバーが停止しているときは端末に保存し、サーバーにつながったら同期する

## 3. 業務ルール（BR-xx）

| ID | ルール |
|---|---|
| BR-01 | 記録の詳細はすべて任意とする。必須にすると記録が続かないため |
| BR-02 | 同じ項目を1日に何回でも記録できる |
| BR-03 | 生成 AI の分析は診断を行わず、判断の材料と受診の目安の提示に留める |
| BR-04 | 生成 AI へのデータ送信は、利用者が実行の操作をしたときだけ行う。送るのは必要な期間の記録とし、写真は送らない |
| BR-05 | 「いつもとの差」の通知は、アプリ起動時の同期が完了した時点で判定し、外れ値があるときだけ出す。同期に失敗したときは判定しない |
| BR-06 | 投薬の通知は、猫ごと・薬ごとに登録した毎日の時刻に行う（F-MD-02） |
| BR-07 | 検知と通知は端末内で行い、サーバーに依存しない。判定には端末にある記録を使う |
| BR-08 | 家族の記録の通知は、同期で自分以外の記録の更新を受け取ったときに出す。同期はアプリの起動中だけ動くので、閉じている間は通知しない（閉じている間に知らせるにはサーバーからのプッシュ通知が要り、C-08 とぶつかる。Ver.1.6.0 で作り、C-08 との兼ね合いはそのときに決める） |
| BR-09 | 通知は Android で行う。Windows はアプリの起動中に画面の中で知らせ、窓が手前になければタスクバーのアイコンを点滅させる（手前に出すと止まる）。Windows で知らせるのは、いつもとの差と誕生日だけとする（ふだんの記録は Android で行うので、記録にかかわる記録忘れ・お薬の時間・家族の記録は Windows では知らせない） |
| BR-10 | 同じ行の変更が競合したときは、サーバーが後から受け取った変更を採用する。端末の時計のずれに左右されないよう、更新日時では比べない |
| BR-11 | 削除も更新の一つとして同期し、BR-10 に従う |
| BR-12 | 「いつもとの差」の通知は、同じ内容を1日に1回までとする |
| BR-13 | 記録忘れは、猫ごとに、その猫の最後の記録（家族の記録を含む）から n 時間が過ぎたときに通知する。n は利用者が設定でき、既定値は10時間で、オフにもできる。通知は記録のたびと、同期で記録を受け取ったときに端末で予約し直す。お別れの猫は対象にしない |
| BR-14 | 写真は期限なしで保存し、端末側で圧縮してから送る。サービスの終了時と、BR-16 で記録を消すときに消える |
| BR-15 | アカウントの削除（退会）時に、その利用者のデータを消す。おうちに投稿した記録の扱いは BR-16 に従う |
| BR-16 | おうちを抜けるとき、または退会するとき、自分が投稿した記録を残すかを本人が選ぶ。残さない場合は本人の投稿だけを消す |
| BR-17 | 記録には投稿時の投稿者名を保存する。アカウントが削除されても、残した記録の投稿者名を表示できるようにする |
| BR-18 | おうちには複数のユーザーと複数の猫を追加できる（例：ユーザー2人と猫2匹） |
| BR-19 | 最後の1人がおうちを抜けるときは確認画面を出し、おうちとその記録をすべて消す |
| BR-20 | 「いつもとの差」の判定方式は、統計的な外れ値と利用者が設定するしきい値から、設定で選ぶ。既定は統計的な外れ値とする。しきい値は猫ごとに持ち、回数は1日の下限と上限、体重は直近の平均からの割合（既定 ±5%）で設定する。統計的な外れ値の計算は BR-31 に従う |
| BR-21 | ユーザーが1人でも、記録はおうちの中で管理する |
| BR-22 | 独自の記録項目はおうちで共有する。ウィジェットのボタンはアカウントに保存し、機種変更でも引き継ぐ |
| BR-23 | おうちの猫が1匹のときは、ウィジェットの猫の選択を省いてワンボタンで記録する |
| BR-24 | 猫のプロフィールの項目はすべて任意とする |
| BR-25 | 亡くなった猫は、記録を残したまま「お別れ」の状態にできる |
| BR-26 | メールアドレスとパスワードは全角を受け付けない。全角が混ざった内容は貼り付けも受け付けない |
| BR-27 | 猫の削除は確認の後に行い、その猫と記録を消す。記録を残す場合は「お別れ」を使う |
| BR-28 | 端末に写真がなくオフラインのときは、オンラインで見られる旨を表示する |
| BR-29 | 削除の確認ではボタンの位置を通常と入れ替える。削除したデータの復元には対応せず、案内もしない |
| BR-30 | 削除の印を付けた行は、90日後にサーバーで物理削除する（写真のファイルも消す）。それより前の位置から同期してきた端末には、全件を取り直させる |
| BR-31 | 統計的な外れ値は、猫ごと・項目ごとに次で判定する。回数（ご飯・水・おしっこ・うんち・吐いた）は、直近28日の1日あたりの回数の平均 ±2標準偏差の外を外れ値とし、前日（記録が出そろった1日）で判定する。上限を超えたかは今日の分でも判定する。体重は、最新の記録が直近28日の平均から ±5% を超えたら外れ値とする。記録が7日分に満たない間は判定しない。薬・ブラシ・独自の項目は判定しない |
| BR-32 | 誕生日（生年月日の月日）には、その猫のお祝いの通知を朝9時に出し（「今日はミケの誕生日です。3歳おめでとう！」。生まれた年の誕生日は出さない。2月29日生まれは、うるう年でない年は2月28日に祝う）、カレンダーの日のセルにアイコンで示す。生年月日が未登録の猫とお別れの猫は対象にしない |
| BR-33 | アプリの更新（F-UP-01・02）は、起動したときと設定の「更新を確かめる」で確かめる。新しい版があれば知らせ、「今すぐ更新」か「5分後にまた知らせる」を選ぶ。更新しなくてもアプリは使える。「5分後」を選んだら、アプリを使っている間に5分後にもう一度知らせる。更新のファイルは、サーバーが返す SHA-256 と一致したときだけ入れる。更新に使ったファイルは、入れた後・取りやめた後・失敗した後のどれでも端末に残さない |
| BR-34 | 版の番号は `<メジャー>.<マイナー>.<パッチ>+<ビルド番号>` とし、出すたびにビルド番号を1つ上げる。新しいかどうかはビルド番号で比べる。上げ方はセマンティック バージョニング（SemVer）に従う：前の版と互換性がなくなるときと、大きな節目となる機能を足すとき（生成 AI 分析）はメジャー、機能を足すときはマイナー、不具合の修正と機能を足さない小さな変更（文言・配置など）はパッチを上げ、上の桁を上げたら下の桁は 0 に戻す。2章のリリースの段階はこの決まりで番号を付ける。1.0.1〜1.0.3 は、この決まりの前に出した Ver.1.1 の途中の版（Android は同じ番号では上書きできないため） |

## 5. データ要件

詳細な列の定義は DB 設計書で行う。

| データ | 主な項目 | サーバー | 端末 |
|---|---|---|---|
| ユーザー | 名前、メールアドレス、パスワードのハッシュ、アイコン | ○ | パスワード以外 |
| ユーザーの設定 | 週の始まり、記録忘れの時間 n、通知の種類ごとのオン・オフ、いつもとの差の判定方式 | ○ | ○ |
| おうち | 名前、作成日時 | ○ | ○ |
| おうちのメンバー | おうち、ユーザー、参加日時 | ○ | ○ |
| 招待 | おうち、トークンのハッシュ、有効期限、使用済みか | ○ | - |
| 猫 | おうち、名前、生年月日、性別、持病、アイコン、状態、いつもとの差のしきい値 | ○ | ○ |
| 投薬の予定 | 猫、薬の名前、量、毎日の時刻、オン・オフ | ○ | ○ |
| 記録項目 | おうち、名前、アイコン、標準か独自か | ○ | ○ |
| 記録 | 猫、記録項目、日時、投稿者 ID、投稿者名、数値、量、追加情報、メモ | ○ | ○（全件） |
| 写真 | 記録、ファイルの場所、サイズ | ○（全件） | 一定期間内のみ |
| ウィジェットのボタン | 記録項目、並び順 | ○ | ○ |
| 未送信の一覧 | 同期待ちの変更 | - | ○ |

- ID は UUID とし、オフラインでも端末で作れるようにする
- 全データに更新日時を持つ。競合はサーバーが受け取った順で解決する（BR-10）
- 削除は印を付けて同期し、印を付けてから90日後にサーバーで物理削除する（BR-11、BR-30）
- 差分の取得には、端末の時計ではなくサーバーが振る通し番号を使う
- 記録は項目ごとに分けず1つの表にまとめ、独自項目を増やしやすくする
- 時刻はサーバーで UTC で保存し、表示時に日本時間へ変換する
- ユーザーの設定はアカウントに保存し、機種変更でも引き継ぐ
- 写真は1つの記録に3枚まで、長辺 1600px 程度に圧縮する（1枚 500KB を目安）
- 端末の写真は30日を過ぎたら消し、サーバーからオンラインのときだけ表示する
- 未送信の写真は、送信が終わるまで端末に保持する
